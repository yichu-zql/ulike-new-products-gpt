# 每周更新操作规程

## 新品入库与选品判断

- 新品要有可辨认的本地图。参考产品用可展示的品牌或授权渠道图片并记录来源。开发概念用标明「开发概念示意」的结构图。
- 市场规模与增速记录对象、地区、周期及来源。实际、估算、相邻品类与预测需明确区分。缺少细分统计时填写参照范围或具体测量路径。累计出货保留期间、增量与系列口径。
- 用户需求写人群、场景、现有方法的缺口和证据。产品存在、痛点存在、需求频率与付费意愿分别验证。海外热门及线下强线上弱均须具备各自对应的渠道证据。
- 新记录填写 decision 的 level、reason、gap、next、criteria、checked，以及 imageKind。优先推进对应买样、做原型或查渠道等低成本动作。定向验证明确升档门槛。暂缓写明重启条件。意向品特征只作同等候选的排序参考。

用户授权：每周一北京时间08:05启动机会新品研究、未上市项目回查、校验、GitHub发布和线上验证。运行位置为本聊天关联的本地电脑，任务通过 Codex 定时功能启动；已创建活动任务「机会新品库每周研究更新」（automation-2），时区Asia/Shanghai。GitHub Actions负责提交后的构建和部署，二者不可混淆。

## 配额和判断

读取 data/update-policy.json 作为唯一配额配置。每批新增医美院线家用化≥7、海外热门≥7、销量起量≥7、需求未满足≥5；一条记录只计一个主方向。运动康复与身体放松≥4是交叉配额，可以包含在前述各方向中。线下热销线上未起量初始建议3个，用户未给硬数量；必须有线下销售依据及明确线上地域、平台、时期的对比证据，缺证据放候选待核实，不强凑。

术原每批研究/复核≥5主推和≥10次推，可以修订已有稳定ID，不把同款重建成新品。护肤品为主、仪器辅助，仪器目标零售价≤300元；参考产品售价与开发目标分开，不把未核实成本写成已达标。每项明确器械ID/结构/交互创新、解决的护肤问题、配套护肤品和证据。新方案不证明功效已验证。

## 运行步骤

1. 进入本仓库，检查 git status 和远程版本，存在用户未提交修改则保留，不覆盖。读取 AGENTS.md，运行 node scripts/weekly.cjs context 获取去重索引与回查队列，后续只读取需要的条目。
2. 按北京时间周一日期建立稳定批次ID weekly-YYYY-MM-DD。相同批次成功应用后重跑直接无变化退出；遇到 .weekly.lock 不自行删除他人锁。
3. 使用联网搜索核实公开来源，优先品牌官网、官方公告、公开渠道数据。销量起量必须记录实际口径、时期；不能把品牌/系列累计销量说成单SKU近期增速。优先新增证据充分的真实产品，不把仅改标题的同款算新增。
4. 仅回查 launch.status=未上市项目。意向品不回查、不因意向标签修改或跟踪状态：每周读取用户标记，提炼技术、场景、人群、耗材和价格偏好来辅助推荐排序，但不能缩小品类和大方向。用户后续反馈时再更新意向标签。每条输出 id、checked（批次日期）、status（verified、inconclusive或blocked）、url、note。网页能访问不代表事实核查完成。inconclusive表示来源已查阅但上市仍不确定，保留原状态；blocked表示来源访问失败，保留旧资料并阻止本批自动发布，通知具体缺口；不能标成已核实。
5. 在仓库 work/candidates/ 下保存候选JSON：id、date、checkedAt（带时区ISO时间）、added（完整新品记录）、revisions（完整修订记录，保留原收录date）、reviews、brief。每个新增/修订记录 evidence 数组含url、claim、checked。旧资料修订附 updates 记录；未上市变化写入 launch。图片缺失保留来源入口，不杜撰图片。
6. node scripts/weekly.cjs check <候选路径>。不足数量、来源异常、缺失回查、重复ID等失败时，保存候选与失败原因，保留上一正式版本。不能降低阈值以通过检查。
7. 通过后 node scripts/weekly.cjs apply <候选路径>，保留 data/releases/ 回退快照，再 npm run build（含数据检查）。只对新增行为补必要测试。备份覆盖仓库数据，不覆盖用户浏览器偏好。
8. 检查 diff，仅提交本批数据、资料和必要资源；git push origin main，禁止强推。等对应 SHA 的 Actions 完成。部署后下载发布产物核对 release.json，并验证页面和本批入口。动作失败不能更新为成功，不把仅推送视为上线。
9. Actions已包含线上内容比对；失败在本聊天说明阶段、批次、配额缺口、保留版本和可恢复动作。成功如无需要用户处理的事项保持简短；无内容变化不制造版本或重复通知。

## 消耗与依赖

不整页抓取旧资料，不读取图片编码；按方向批量搜索、复用已核实来源摘要，以稳定ID去重。只重新研究新候选、意向偏好和未上市状态及影响判断的旧证据。没有实质变更则不重复发布。图片仅在新条目缺少必要参考或来源失效时更新。

本地任务依赖电脑可用、应用调度、联网访问和有效GitHub登录/权限。配额是质量门槛，不是承诺每周一定存在足够真实新品。失败通知由定时任务的聊天通知承载；若电脑离线导致任务根本未启动，不能承诺在计划时刻即时发送失败消息。
