# 维护说明

## 日常更新入口

产品资料在 `data/products.json`。保留已有稳定 ID，新增记录使用全新 ID。字段说明：`date` 为收录期次；`days[].brief` 为当期动态；`summary` 为表格简述；`market` 为规模、增长、需求和判断；`launch.checked` 为上市信息核查时间；`updates` 为资料修订记录。数据所属日期不等于采集或部署日期。

图片放入 `assets/images/`，数据中的 `img` 使用相对路径。没图时不填虚假图片，沿用查看参考来源或待补占位。原图来源链接保留于 `image_page` 与 `image_url`。

## 复刻基准与后续变更

当前验证器刻意锁定这次复刻基准，包括完整数据指纹、原图字节指纹、原样 CSS、除两处明确差异外的交互脚本。它可阻止未审查的“顺便改了内容”。

未来有意更新数据、样式或逻辑时，先保留本次发布提交和原始 `data/provenance.json`，再更新对应来源记录、版本说明、校验断言与测试预期。不要仅为通过校验而删除校验或冒充原版指纹。新的基准应记录自己的变更依据和数据截止日期，而不是继续声明与旧原版逐字一致。更新副标题中的截止时间必须以实际数据为依据。

## 发布与回退

1. 检查当前分支及未提交修改，确认远程 `main` 没有新的工作。
2. 完成数据或界面修改，运行 `npm test` 和 `npm run build`（构建已包含同一套校验，无变化时不必重复）。
3. 检查 `dist/` 只包含页面和静态资源，检查子路径资源。
4. 提交并推送；GitHub Actions 通过后自动部署 Pages。
5. 到正式网址检查主视角、筛选、详情、手机宽表与图片。
6. 出现问题时，使用 `git revert <异常提交>` 生成回退提交并推送，等待同样流程重新部署。保留历史，不使用强推改写线上版本记录。

## 已知边界

- 本版没有定时研究或采集链路。要实现原站文案中的每周一 08:05（北京时间）更新，需要另行确定来源、采集运行环境、校验、候选审核、失败通知和发布机制；不要只改时间标签。
- 原版的未上市专区与本期更新按全库计算，清单与详情局部筛选独立，筛选选项计数按视角统计。本版忠实保留。
- 原版 HTML 使用 quirks 文档模式且没有移动 viewport 标签，本版保留。窄窗口 520px CSS 断点可验收，但真实手机的默认缩放由设备浏览器决定；若要求标准手机 viewport，需要作为单独适配变更验证。
- 原版未上市卡片使用 role=button，但未绑定 Enter/Space 激活；可用鼠标、触屏点击，弹窗可按 Escape 关闭。若补齐此项无障碍行为，应作为明确的后续差异。
- 原版市场分级和需求/推荐结论为预先整理的研究字段，不自动从文本重算；本轮未做全量外链可用性和业务事实审计。
- 页内关键词搜索与视角偏好在访问者浏览器运行；没有向外部 AI 服务传送资料。
